**결론.** 롯데그룹 계열 세븐일레븐의 추가 출점은 **현재 보류**한다. 실사를 한다면 **A 구간(대방역 접근 골목 입구)을 먼저** 본다. 근거는 `market_entry_strategy.pdf`에 정리했다. 규칙 시뮬레이션과 LLM(Groq `qwen/qwen3.8-27b`) 판단이 모두 같은 결론(보류, A)을 냈다.

**사실 확인 원칙.** 실제 존재가 확인되지 않은 점포나 브랜드는 지도에 넣지 않았다. 점포 좌표는 공개 지도 등록 자료로, 현재 영업 여부는 보증하지 않는다. 가정으로 넣은 값은 모두 "가정"이라고 표시했다.

## 3. 지도를 만든 방법

1. **좌표계.** 모든 레이어를 WGS84 위경도로 맞추고, 화면에는 Web Mercator로 그렸다. 위성 타일과 정확히 겹친다.
2. **도로.** OSM `highway` 등급을 대로·보조·골목·서비스·보행로·계단 6단계로 묶고 실제 폭(대로 24m, 골목 7m 등)으로 그렸다. 확대하면 도로명이 도로 방향을 따라 나타나고, 겹치는 이름은 자동으로 뺀다.
3. **건물.** Overture 윤곽에 OSM 이름·층수를 붙였다. 층수가 등록된 건물은 실제 층수 × 3.2m 높이로 세웠다. 층수가 없는 건물은 모두 같은 기본 높이(2층)로 그렸다. 남쪽 건물이 북쪽 건물을 가리도록 북→남 순서로 벽, 지붕 순서대로 칠하는 2.5D 방식이다.
4. **토지이용·교통.** 주거·상업·학교·병원·공원·주차장을 색으로 구분했다. 1호선 대방역·신림선 대방역, 출구 번호, 버스정류장을 아이콘으로 표시했다.
5. **성능.** 지도(배경 레이어)는 확대·이동할 때만 다시 그리고, 사람 이동은 매 프레임 위에 덧그린다.
6. **클릭 정보.** 점포는 출처 링크, 건물은 층수·윤곽 출처, 정류장·출구, 이동 중인 사람은 페르소나를 보여준다.

## 4. 시뮬레이션 방법

### 4.1 흐름

```
[새 페르소나로 실행] → 새 시드 → 3,961명 풀에서 N명(100/200/400) 무작위 추출
  → 사람마다: ① 오늘 상권에 올까? ② 몇 시에? ③ 어떤 업종? ④ 어느 점포? ⑤ 살까?
  → 00:00부터 24:00까지 시계가 흐르며 정한 시각에 출발, 도보 네트워크 최단경로로 이동
```

시드를 입력하면 같은 사람들이 뽑혀 같은 결과가 재현된다(발표·보고서용).

### 4.2 결정 규칙 (1단계 노트북 `04-store-visit-sim` 규칙 재사용, 정답표 미참고)

| 단계 | 규칙 |
|---|---|
| ① 방문 여부 | 기본 30% + 나이 가감(20대 +20, 30대 +15, 40대 +5, 50대 −5, 60대+ −15%p) + 취미·페르소나 문장의 긍정 키워드(쇼핑·카페·맛집·산책…) 1개당 +4%p, 부정 키워드(집에서·혼자·독서…) 1개당 −5%p. 2~95%로 제한 |
| ② 방문 시각 | 연령대별 시간대 가중치표 (예: 20대는 17–21시 32%, 60대+는 06–11시 28%) |
| ③ 업종 | 연령대별 업종 가중치 × (1 + 0.3 × 업종 키워드 수). 상권정보의 대표 운영시간 밖이면 제외 (편의점·숙박 24시간, 카페 8–22시, 음식점 10–22시, 슈퍼마켓 9–23시). 음식점 가중치는 이번에 새로 둔 가정(전 연령 1.0) |
| ④ 점포 | 같은 업종 안에서 도보 거리 감쇠 exp(−거리/220m) × 매력도. 기존 점포 1, 신규 후보는 "신규점 매력도" 슬라이더(기본 1.0) |
| ⑤ 구매 | 편의점 방문 시 85% 확률로 7,000원 구매 (시연용 가정) |
| 출발지 | 대방역 출입구 50% · 건물 윤곽 50% (시연용 가정. 전국 페르소나를 이 동네 주민으로 해석하지 않음) |

### 4.3 반복 비교

"반복 비교 실행"은 애니메이션 없이 50~300일을 즉시 계산한다. **같은 날(시드)을 A·B·C에 똑같이 적용**하는 쌍대 비교라 후보 차이만 비교된다.

| 후보 | 매력도 ×1.0 하루 평균 후보 방문 | 편의점 점유 | 매력도 ×1.5 | 점유 |
|---|---:|---:|---:|---:|
| A | 2.27명 | 15.6% | 3.11명 | 21.3% |
| B | 1.47명 | 10.2% | 2.16명 | 14.7% |
| C | 1.47명 | 10.2% | 2.03명 | 14.1% |

*200명 × 300일, 시작 시드 20260923. 표본 인원 기준 상대 비교이며 실제 매출 예측이 아니다.*

### 4.4 LLM 에이전트 판단 (교차 검증)

사이트의 규칙 시뮬레이션과 별개로, LLM이 직접 판단하게 해서 결론을 교차 확인했다(`scripts/llm_store_choice.py`).

1. **에이전트 판단:** 같은 페르소나 풀에서 150명(고정 시드 20261007)을 뽑았다. 상권 정보와 A·B·C 후보 설명, 인물 정보(나이·성별·직업·가족·소개·취미)를 주고 물었다. "새 세븐일레븐이 생기면 A/B/C 중 어디를 쓰겠나, 아니면 **기존 편의점**을 계속 쓰겠나, 주로 몇 시, 이유는?" 5명씩 묶어 독립 판단을 지시했고, 비율을 맞추지 말라고 했다. "기존" 선택지는 LLM의 긍정 편향을 막기 위해 넣었다.
2. **진출 판단:** 손익 가정, 규칙 시뮬레이션 결과, 1번 결과를 모두 주고 "진출해도 되는가, 어디에, 누구에게, 어떻게"를 JSON으로 받았다. 근거에 없는 숫자는 만들지 말라고 지시했다.

| 선택 | A | B | C | 기존 편의점 |
|---|---:|---:|---:|---:|
| 150명 비율 | **32.7%** | 5.3% | 1.3% | 60.7% |

- 20–30대는 약 60%가 A를 골랐고, 60대 이상은 86%가 기존 편의점을 유지했다.
- 새 점포를 고른 사람의 49%가 17–21시에 이용하겠다고 했다. 가장 흔한 이유는 "퇴근 후 역→집 동선"이었다.
- LLM 진출 판단은 **보류, 추천 위치 A**였다.
- 한계: 일부 응답이 페르소나에 없는 거주지를 지어냈다. LLM이 주말 비중(2일 합계)을 하루 값처럼 잘못 해석한 부분도 있었다. 그래서 LLM 결과는 교차 확인 근거로만 쓴다.
- 사용량: 31회 호출, 45,723 토큰(무료 한도 안). 전체 프롬프트·응답은 작업 패키지의 `outputs/llm_choice.json`에 있다.
- **사이트는 이 결과를 정적으로 보여줄 뿐이고, 방문자가 볼 때 API를 호출하지 않는다.** 그래서 API 키가 필요 없다.

### 4.5 손익 계산기

```
월 매출    = 점포 앞 통행량 × 입점률 × 구매율 × 객단가 × 30일
월 영업잉여 = 월 매출 × 순공헌이익률 − 월 고정비
```
기준 가정(통행 2,500회/일, 입점 6.5%, 구매 85%, 7,000원, 25%, 750만원)에서 월 매출 2,900.6만원, 영업잉여 −24.8만원. 모든 값은 연구용 가정이며 웹에서 바꿀 수 있다.

## 6. 검증

- 후보 3곳이 모두 공식 상권 경계 안에 있는지 확인했다.
- 도보 경로가 실제 도로 그래프의 연결된 간선만 따르는지 확인했다(임의 직선 이동 없음).
- 새로 받은 OSM의 분석용 점포 목록이 이전 스냅숏과 동일해서, 후보 거리·점포 수가 바뀌지 않았다.
- 손익 시나리오 값을 코드로 재계산해 일치하는지 확인했다(기준 월 매출 29,006,250원).
- 브라우저 자동 검사로 다음을 확인했다: 같은 시드를 넣으면 같은 사람이 뽑힌다. 새 실행 때는 다른 사람이 뽑힌다. 후보를 바꾸면 초기화된다. 반복 비교는 3행을 출력한다. CSV 다운로드가 된다. 모바일에서 가로 넘침이 없다. JS 오류는 0건이다.

## 7. 한계

- 점포 좌표는 공개 지도 등록 자료이며 현재 영업·폐업은 현장 확인이 필요하다. 상권 경계는 2023 배포본이다.
- ML 추출 건물 윤곽은 형태 추정치이고, 층수 미등록 건물의 높이는 실제가 아니다.
- 방문확률·시간대·업종 선호는 상식 기반 규칙이다. 숙박시설 방문 비중(약 25%)은 1단계 호텔 가중치를 그대로 쓴 탓에 높게 나올 수 있다.
- 시뮬레이션 숫자는 표본 인원 기준이며, 실제 상권 인구로 확대한 방문수·매출이 아니다.
- 임대료, 점포 앞 통행량, 구매율, 가맹 조건은 실측이 없다. 실제 출점 판단 전에 확보해야 한다.
