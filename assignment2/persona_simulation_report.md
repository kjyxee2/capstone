# 페르소나 에이전트 멀티 대화 시뮬레이션

Nemotron-Personas-Korea 데이터셋의 가상 주민을 LLM 에이전트로 만들어, 특정 상황에서 서로 대화·행동하게 하고 **상용 API 모델**과 **로컬 3B 모델**의 결과를 비교한 실험입니다.

## 실험 설계

### 데이터셋
- **출처**: nvidia/Nemotron-Personas-Korea (HuggingFace, CC BY 4.0)
- **규모**: 100만 명의 한국인 가상 페르소나
- 각 주민은 나이·성별·직업·거주지 등 기본 정보와 함께 상세한 페르소나 텍스트를 보유

### 등장 인물 (데이터셋에서 실제 추출)

| 이름 | 나이 | 직업 | 거주지 | 시뮬레이션 내 역할 |
|------|------|------|--------|-------------------|
| 오준서 | 24세 | 공연·영화 및 음반 기획자 | 충청남-계룡시 | 면세품을 찾으러 온 손님 (최애 주민) |
| 박현주 | 35세 | 그 외 상점 판매원 | 경기-광명시 | 면세점 픽업 데스크 직원 |
| 이은애 | 38세 | 무직 (주부) | 경기-김포시 | 오준서 뒷순번 대기 손님 |

### 상황 설정
> 롯데면세점 인터넷면세점 상품 수령 데스크. 오준서는 일본 여행을 앞두고 인터넷으로 구매한 면세품을 찾으러 왔다. 박현주는 이를 응대하는 직원이다. 이은애는 오준서 바로 뒷순번으로 자신의 물건을 찾기 위해 대기 중이다.

### 방법
- 각 주민의 페르소나 텍스트를 시스템 프롬프트로 주입하여 역할극 수행
- 오준서 → 박현주 → 이은애 순서로 3턴(총 9개 대사) 진행
- 직전까지의 대화 로그를 매 턴 전달하여 맥락을 유지
- 성격 힌트를 별도로 주입하지 않고, **오직 데이터셋 페르소나 원문만으로** 캐릭터가 자율적으로 행동하도록 설계

### 비교 모델

| 구분 | 모델 | 실행 환경 |
|------|------|-----------|
| 상용 API | Llama-3.3-70B-Versatile | Groq API (클라우드) |
| 로컬 3B | Qwen2.5-3B-Instruct | Colab T4 GPU (로컬) |

## 결과 1: 상용 API (Llama-3.3-70B)

**턴 1**
- **오준서**: 박현주, 안녕하세요. 오준서입니다. 저기요, 제가 인터넷으로 구매한 면세품 수령하러 왔는데요, 확인해 주실 수 있을까요? *[구매내역 화면을 보여주는 스마트폰을 꺼냄]*
- **박현주**: 오준서님, 안녕하세요. 저는 박현주입니다. 잠시만 기다려주세요, 주문번호와 성함으로 확인해 보겠습니다. *[컴퓨터 화면을 확인하며 키보드를 타이핑함]*
- **이은애**: 박현주, 안녕하세요. 저는 이은애입니다. 혹시 제가 찾으러 온 상품도 확인해 줄 수 있을까요? *[지갑에서 주문 확인서를 꺼냄]*

**턴 2**
- **오준서**: 박현주, 죄송한데요, 지금 제 차례 아닌가요? *[조금 앞으로 걸어가며 질문함]*
- **박현주**: 오준서님, 잠시만 기다려주세요. 저는 지금 오준서님의 주문번호를 확인 중이니까요. 이은애님, 먼저 오준서님께 응대하겠습니다. 잠시만 기다려 주세요.
- **이은애**: 박현주, 죄송해요. 주문번호를 확인해 주셔야 제가 상품을 수령할 수 있잖아요. *[주문 확인서를 더 가까이 보여줌]*

**턴 3**
- **오준서**: 박현주, 죄송한데요, 제 차례인데요, 제 주문번호를 확인해 주시면 안 될까요? *[조금 더 앞으로 나서며 스마트폰을 다시 보여줌]*
- **박현주**: 오준서님, 잠시만 더 기다려 주세요. 제가 지금 주문번호를 확인하고 있습니다. 이은애님, 잠시만 더 기다려 주세요. 순서대로 처리하겠습니다.
- **이은애**: 박현주, 오준서님이 주문번호 확인을 마치셨으니 이제 제가 상품을 찾으러 왔어요. 주문 확인서를 보여드릴게요. *[주문 확인서를 더 가까이 보여줌]*

## 결과 2: 로컬 3B (Qwen2.5-3B)

**턴 1**
- **오준서**: 안녕하세요, 저기요. 일본 여행 준비를 위해 인터넷으로 주문한 면세품을 찾으러 왔어요. 선생님, 혹시 저의 차례가 왔나요? *[고개를 젓고, 손님으로부터 조금 떨어져 서서 기다림]*
- **박현주**: 저기요, 안녕하세요. 일본 여행 준비를 위해 인터넷으로 주문한 제품을 확인하러 왔습니다. 고객님, 혹시 제가 차례가 왔나요? *[손님에게 다가가서 서서 기다림]*
- **이은애**: 이은애: 안녕하세요, 저기요. 일본 여행 준비를 위해 인터넷으로 주문한 제품을 확인하러 왔어요. 고객님, 혹시 저의 차례가 왔나요?

**턴 2~3** (반복 루프에 빠짐)
- 세 인물 모두 "고객님, 혹시 저의 차례가 왔나요?"라는 거의 동일한 문장을 반복
- 직원인 박현주까지 자신이 손님인 것처럼 "제가 차례가 왔나요?"라고 발화
- 이름이 "이은애: 이은애:"처럼 중복 출력되는 포맷 오류 발생

## 비교 분석

### 평가 항목별 비교

| 평가 항목 | 상용 API (Llama 70B) | 로컬 3B (Qwen2.5) |
|-----------|---------------------|-------------------|
| **역할 구분** (손님/직원) | 명확히 유지 — 손님은 요청, 직원은 조회·응대 | 붕괴 — 직원 박현주가 자신을 손님처럼 발화 |
| **상황 이해** | 면세점 픽업 맥락에 정확히 집중 | 표면적 이해, "차례" 개념에만 매몰 |
| **대화의 유의미성** | 앞 발화에 반응하며 순서 갈등이 전개됨 | 서로 반응 없이 유사 문장 반복 (루프) |
| **맥락 유지** | 3턴 내내 일관된 상황 진행 | 2턴부터 대화가 정체·반복 |
| **포맷 안정성** | 이름·형식 오류 없음 | "이은애: 이은애:" 중복 출력 오류 |
| **지시 준수** (호칭 등) | "선생님" 미사용, 규칙 준수 | "선생님" 재등장 등 지시 위반 |

### 페르소나 반영도

두 모델 모두 **데이터셋 페르소나의 개성(오준서의 기획자 감각, 박현주의 실속형 판매원 성향, 이은애의 바쁜 주부 특성)이 대사에 뚜렷하게 드러나지는 않았다.** 다만 상용 API는 최소한 각자의 **역할(손님/직원)에 맞는 발화 패턴**은 일관되게 유지한 반면, 로컬 3B는 역할 자체가 뒤섞여 페르소나 이전에 기본적인 배역 구분에도 실패했다.

이는 성격 힌트를 별도로 주입하지 않고 페르소나 원문만 제공했기 때문으로, "페르소나 텍스트만으로는 표면적 개성 재현에 한계가 있다"는 점을 시사한다.

### 유의미한 소통 여부

- **상용 API**: 오준서가 "제 차례 아닌가요?"라며 순서를 재촉하고, 직원이 "순서대로 처리하겠습니다"라며 중재하는 등 **실제 대기 상황에서 발생할 법한 순서 갈등이 자연스럽게 전개**되었다. 에이전트 간 상호작용이 유의미하게 작동한 사례다.
- **로컬 3B**: 세 에이전트가 서로의 발화에 반응하지 않고 거의 동일한 문장을 반복하여, **상호작용이라기보다 독백의 나열**에 가까웠다.

## 결론

동일한 페르소나와 상황을 제공했을 때, **모델 규모에 따른 시뮬레이션 품질 차이가 매우 뚜렷하게 나타났다.**

상용 API(70B)는 역할 구분, 맥락 유지, 에이전트 간 갈등 전개 등 멀티 에이전트 시뮬레이션에 필요한 기본 요건을 안정적으로 충족했다. 반면 로컬 3B는 역할 붕괴와 반복 루프로 인해 유의미한 상호작용을 만들어내지 못했다.

다만 **페르소나의 세밀한 개성 반영**이라는 측면에서는 상용 API조차 표면적 재현에 그쳤으며, 이는 페르소나 원문 주입만으로는 부족하고 추가적인 성격 강조 프롬프트나 파인튜닝이 필요함을 시사한다. 소규모 로컬 모델로 페르소나 에이전트 시뮬레이션을 구현하려면 역할 고정, 반복 억제 등 별도의 제어 장치가 필수적이라는 점도 확인되었다.
